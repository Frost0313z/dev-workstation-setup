# 개발 워크스테이션 미션 — 용어 정리

작성 2026-11-02. 미션 안내문에 나오는 용어를 초보자 눈높이로 풀었다.
각 용어는 **뜻 → 왜 필요한가 → 예시** 순서다. 맨 아래에 시험 대비 모범 답안이 있다.

---

## 1. 큰 그림

### 개발 워크스테이션
개발에 필요한 도구(터미널·Docker·Git)가 세팅된 내 컴퓨터 환경.
"코드가 내 컴퓨터에서만 돌아가는" 문제를 없애고, 팀원 누구나 같은 방식으로 실행하게 만드는 것이 목표.

### CLI (Command Line Interface, 명령줄 인터페이스)
마우스 대신 **글자로 명령을 쳐서** 컴퓨터를 조작하는 방식. 반대말은 GUI(그래픽 인터페이스, 마우스 클릭).
터미널 = CLI 를 쓰는 프로그램. 쉘(bash, zsh, PowerShell) = 터미널 안에서 명령을 해석해 주는 프로그램.

### 재현성 (Reproducibility)
같은 절차를 따르면 **누가, 몇 번을 해도 같은 결과**가 나오는 성질.
Docker 와 README 가 둘 다 이걸 위해 있다. 심사 기준에도 "README만 보고 따라 할 수 있어야 한다"고 적혀 있다.

### sudo
리눅스에서 **관리자 권한으로 명령을 실행**하는 접두어. "superuser do".
서울캠퍼스는 보안상 sudo 를 막아서 OrbStack(sudo 없이 Docker 를 돌리는 맥 전용 앱)을 쓴다. Windows 는 Docker Desktop 을 쓴다.

## 2. 터미널 · 리눅스 기본

| 명령 | 뜻 | 예시 |
|---|---|---|
| `pwd` | 지금 내가 있는 폴더 위치 출력 (print working directory) | `/home/user` |
| `ls` | 폴더 안 목록 보기 (list) | `ls -la` = 숨김 파일 포함(-a) + 자세히(-l) |
| `cd` | 폴더 이동 (change directory) | `cd ~/codyssey` |
| `mkdir` | 폴더 만들기 (make directory) | `mkdir -p a/b/c` = 중간 폴더까지 한 번에 |
| `touch` | 빈 파일 만들기 (또는 수정 시각 갱신) | `touch memo.txt` |
| `cp` | 복사 (copy) | `cp a.txt b.txt`, 폴더는 `cp -r` |
| `mv` | 이동 **또는 이름 변경** (move) | `mv old.txt new.txt` |
| `rm` | 삭제 (remove). 휴지통 없음, 바로 사라짐 | `rm a.txt`, 폴더는 `rm -r` |
| `cat` | 파일 내용 출력 (concatenate) | `cat memo.txt` |
| `echo` | 글자 출력. `>` 와 함께 파일에 쓰기 | `echo hi > hello.txt` |

### 숨김 파일
이름이 `.` 으로 시작하는 파일/폴더. `ls` 로는 안 보이고 `ls -a` 로 보인다.
예: `.git` (Git 저장소 데이터), `.env` (환경 변수), `.bashrc` (쉘 설정).

### 홈 디렉토리 `~`
로그인한 사용자의 기본 폴더. 리눅스는 `/home/사용자명`, 맥은 `/Users/사용자명`, Windows 는 `C:\Users\사용자명`.
`~` 한 글자가 이 경로의 줄임말.

### 절대 경로 vs 상대 경로
- **절대 경로**: 맨 꼭대기(`/`)부터 적은 전체 주소. 어디서 치든 같은 곳을 가리킨다. 예: `/home/user/codyssey/app`
- **상대 경로**: **지금 내 위치 기준**으로 적은 주소. 내 위치가 바뀌면 가리키는 곳도 바뀐다. 예: `./app`, `../docs`
- `.` = 현재 폴더, `..` = 한 단계 위 폴더

비유: 절대 경로는 "서울시 강남구 테헤란로 1" 같은 주소, 상대 경로는 "여기서 왼쪽 두 번째 집".

## 3. 파일 권한

### r / w / x
- **r** (read, 4): 읽기. 파일 내용을 볼 수 있다 / 폴더 목록을 볼 수 있다.
- **w** (write, 2): 쓰기. 파일을 고칠 수 있다 / 폴더 안에 파일을 만들고 지울 수 있다.
- **x** (execute, 1): 실행. 파일을 프로그램으로 실행할 수 있다 / 폴더 **안으로 들어갈(cd) 수 있다**.

### 소유자 / 그룹 / 기타
권한은 세 부류에게 따로 준다.
1. **소유자(owner, u)**: 파일을 만든 사람
2. **그룹(group, g)**: 소유자가 속한 그룹
3. **기타(others, o)**: 나머지 모든 사람

### `ls -l` 출력 읽는 법
```
-rwxr-xr--  1 user group  120 Nov  2 10:00 run.sh
│└┬┘└┬┘└┬┘
│ │  │  └ 기타: r--  (읽기만)
│ │  └ 그룹: r-x    (읽기 + 실행)
│ └ 소유자: rwx     (전부)
└ 맨 앞 글자: - 는 파일, d 는 디렉토리
```

### 숫자 표기 (755, 644)
r=4, w=2, x=1 을 **더해서** 한 자리씩 쓴다. 자릿수 순서는 소유자·그룹·기타.

| 표기 | 소유자 | 그룹 | 기타 | 보통 쓰는 곳 |
|---|---|---|---|---|
| **755** | rwx (7) | r-x (5) | r-x (5) | 실행 파일, 디렉토리 |
| **644** | rw- (6) | r-- (4) | r-- (4) | 일반 문서·설정 파일 |
| 777 | rwx | rwx | rwx | 아무나 다 가능. 보안상 피한다 |
| 600 | rw- | --- | --- | 비밀키 등 나만 봐야 하는 파일 |

### chmod / chown
- `chmod` (change mode): 권한 변경. `chmod 644 memo.txt`, `chmod +x run.sh`
- `chown` (change owner): 소유자 변경. `chown user:group 파일`

## 4. Docker 핵심 개념

### 컨테이너 (Container)
프로그램과 그 실행에 필요한 것(라이브러리·설정)을 **한 상자에 격리해서** 돌리는 기술.
내 컴퓨터 OS 위에서 돌지만, 안에서는 자기만의 작은 리눅스처럼 보인다. 가상 머신보다 훨씬 가볍고 빠르다.

### 이미지 (Image)
컨테이너를 만들기 위한 **설계도이자 틀**. 읽기 전용. 한 이미지로 컨테이너를 몇 개든 찍어낼 수 있다.
비유: 이미지 = 붕어빵 틀, 컨테이너 = 구워진 붕어빵.

### 이미지와 컨테이너의 분리 (왜 나누나)
틀은 변하지 않고, 붕어빵은 먹으면 없어진다. 이미지는 그대로 두고 컨테이너만 지웠다 만들면 **항상 같은 상태에서 다시 시작**할 수 있다. 이게 재현성의 핵심.

### 격리된 실행 환경
컨테이너 안의 파일·프로세스·네트워크는 밖(호스트)과 분리돼 있다. 컨테이너 안에서 파일을 지워도 내 컴퓨터는 멀쩡하다. 반대로 **컨테이너를 지우면 안에 쓴 데이터도 사라진다** (그래서 볼륨이 필요).

### 호스트 (Host)
컨테이너를 돌리는 **내 컴퓨터**. "호스트 포트", "호스트 폴더"는 전부 내 컴퓨터 쪽을 뜻한다.

### Docker 데몬 (Docker Engine)
뒤에서 계속 돌면서 컨테이너를 실제로 관리하는 프로그램. `docker` 명령은 이 데몬에게 부탁을 전달할 뿐이다.
`docker info` 가 성공하면 데몬이 살아 있다는 뜻. Windows 에서는 Docker Desktop 을 켜야 데몬이 뜬다.

### Docker Hub / 레지스트리
이미지를 올리고 내려받는 **공용 창고**. `docker pull nginx` 는 Docker Hub 에서 nginx 이미지를 받아오는 것.

### hello-world
Docker 가 제대로 설치됐는지 확인하는 가장 작은 공식 이미지. 실행하면 "Hello from Docker!" 를 출력하고 끝난다.

### 베이스 이미지 (Base Image)
내 이미지를 만들 때 **출발점으로 삼는 기존 이미지**. `FROM nginx:alpine` 에서 nginx:alpine 이 베이스.
- `nginx`, `apache`: 웹 서버가 이미 들어 있음
- `ubuntu`, `alpine`: 깡통 리눅스. alpine 은 아주 작은(5MB) 리눅스

### 태그 (Tag)
이미지의 버전 이름. `이미지명:태그` 형식. `nginx:alpine`, `my-web:1.0`. 생략하면 `latest`.

## 5. Docker 명령어

| 명령 | 뜻 |
|---|---|
| `docker --version` | 설치된 Docker 버전 |
| `docker info` | 데몬 상태·컨테이너 수·저장 경로 등 전체 점검 |
| `docker pull 이미지` | 이미지 내려받기 |
| `docker images` | 내 컴퓨터에 있는 이미지 목록 |
| `docker build -t 이름:태그 .` | 현재 폴더(`.`)의 Dockerfile 로 이미지 만들기. `-t` 는 이름 붙이기 |
| `docker run 이미지` | 이미지로 컨테이너 만들고 실행 |
| `docker ps` | **실행 중인** 컨테이너 목록 |
| `docker ps -a` | 멈춘 것 포함 **전체** 컨테이너 목록 |
| `docker stop 이름` | 컨테이너 정지 |
| `docker start 이름` | 멈춘 컨테이너 다시 시작 |
| `docker rm 이름` | 컨테이너 삭제. `-f` 는 실행 중이어도 강제 삭제 |
| `docker rmi 이미지` | 이미지 삭제 |
| `docker logs 이름` | 컨테이너가 출력한 내용 보기. `-f` 는 실시간 |
| `docker stats` | CPU·메모리 사용량 실시간 표 |
| `docker exec -it 이름 명령` | 실행 중인 컨테이너 **안에서** 명령 실행 |
| `docker attach 이름` | 컨테이너의 메인 프로세스 화면에 **붙기** |
| `docker volume create 이름` | 볼륨 만들기 |
| `docker volume ls` | 볼륨 목록 |

### `docker run` 자주 쓰는 옵션
- `-d` (detach): 백그라운드로 실행. 터미널이 바로 돌아온다
- `-it`: 터미널을 연결해서 안에서 직접 타이핑 (`-i` 입력 유지 + `-t` 터미널 흉내)
- `--name 이름`: 컨테이너에 이름 붙이기 (안 붙이면 랜덤 이름)
- `-p 호스트:컨테이너`: 포트 매핑
- `-v 볼륨:경로` 또는 `-v 호스트경로:컨테이너경로`: 스토리지 연결
- `--rm`: 끝나면 자동 삭제
- `-e 이름=값`: 환경 변수 주입

### attach 와 exec 의 차이 (과제에서 "스스로 관찰하라"는 항목)
- **attach**: 컨테이너가 원래 돌리던 **메인 프로세스(PID 1)에 붙는다**. 여기서 `exit` 하면 메인 프로세스가 끝나서 **컨테이너도 종료**된다.
- **exec**: 컨테이너 안에 **새 프로세스를 하나 더** 띄운다. 여기서 `exit` 해도 메인 프로세스는 그대로라 **컨테이너는 계속 산다**.
- 실무에서는 거의 항상 `exec -it 이름 bash` 를 쓴다.

### 컨테이너가 바로 꺼지는 이유
컨테이너는 **메인 프로세스가 끝나면 같이 끝난다**. `docker run ubuntu` 만 치면 할 일이 없어서 즉시 종료.
그래서 예시에 `sleep infinity` (영원히 대기) 를 붙여 살려 둔다.

## 6. Dockerfile

### Dockerfile
이미지를 **어떻게 만들지 적은 레시피 파일**. 파일명은 정확히 `Dockerfile` (확장자 없음).
"기존 Dockerfile 기반 커스텀 이미지" = 남이 만든 베이스 이미지 위에 내 파일·설정을 얹은 것.

### 주요 명령어

| 명령 | 뜻 | 예시 |
|---|---|---|
| `FROM` | 베이스 이미지. **맨 첫 줄 필수** | `FROM nginx:alpine` |
| `LABEL` | 이미지에 메모 붙이기 | `LABEL org.opencontainers.image.title="my-web"` |
| `ENV` | 환경 변수 설정 | `ENV APP_ENV=dev` |
| `COPY` | 내 컴퓨터 파일을 이미지 안으로 복사 | `COPY site/ /usr/share/nginx/html/` |
| `RUN` | 이미지를 **만드는 중에** 명령 실행 (패키지 설치 등) | `RUN apt-get update && apt-get install -y curl` |
| `WORKDIR` | 이후 명령의 기준 폴더 | `WORKDIR /app` |
| `EXPOSE` | "이 포트를 쓴다"는 **문서용 표시**. 실제로 열지는 않는다 | `EXPOSE 80` |
| `CMD` | 컨테이너가 **시작될 때** 실행할 명령 | `CMD ["nginx", "-g", "daemon off;"]` |
| `USER` | 이후 명령을 실행할 사용자 (root 대신) | `USER appuser` |
| `HEALTHCHECK` | 컨테이너가 건강한지 주기적으로 검사 | `HEALTHCHECK CMD curl -f http://localhost/ \|\| exit 1` |

### RUN 과 CMD 의 차이
- `RUN`: **빌드할 때** 한 번. 결과가 이미지에 구워진다.
- `CMD`: **컨테이너 켤 때마다**. 이미지에는 "이걸 실행해라"는 지시만 남는다.

### 빌드 컨텍스트
`docker build ... .` 의 마지막 `.`. Dockerfile 과 COPY 할 파일들이 있는 폴더. 이 폴더 밖의 파일은 COPY 못 한다.

### 레이어 (Layer)
Dockerfile 의 한 줄 한 줄이 이미지의 한 층이 된다. 바뀌지 않은 층은 **캐시**돼서 다음 빌드가 빨라진다.

## 7. 포트 매핑 · 네트워크

### 포트 (Port)
한 컴퓨터 안에서 **어느 프로그램에게 보낼 요청인지** 구분하는 번호(0~65535). 아파트 호수 같은 것.
- 80: HTTP(웹), 443: HTTPS, 22: SSH, 5000·8080: 개발용으로 자주 씀

### localhost
**내 컴퓨터 자신**을 가리키는 주소. IP 로는 `127.0.0.1`.

### 포트 매핑 (`-p 호스트포트:컨테이너포트`)
컨테이너는 격리돼 있어서 **안에서 웹 서버가 떠 있어도 밖에서 못 들어간다**.
`-p 8080:80` 은 "내 컴퓨터 8080 번으로 오는 요청을 컨테이너 80 번으로 넘겨라"는 뜻.
그래서 브라우저에서 `http://localhost:8080` 을 치면 컨테이너 안 웹 서버가 응답한다.

### 왜 필요한가 (시험 포인트)
1. 격리: 컨테이너 네트워크는 기본적으로 외부와 끊겨 있다
2. 충돌 방지: 같은 이미지를 `-p 8080:80`, `-p 8081:80` 으로 **두 개 동시에** 띄울 수 있다. 과제의 "포트 매핑 접속 2회"가 이것.

### curl
터미널에서 웹 주소에 요청을 보내고 응답을 글자로 받는 도구. 브라우저 없이 "서버가 응답하나" 확인할 때 쓴다.
`curl http://localhost:8080`

## 8. 스토리지 · 데이터 영속성

### 영속성 (Persistence)
컨테이너를 지워도 **데이터가 남아 있는 성질**. 컨테이너 안에 쓴 파일은 기본적으로 컨테이너와 함께 사라진다.

### 바인드 마운트 (Bind Mount)
**내 컴퓨터의 특정 폴더**를 컨테이너 안의 경로에 그대로 연결.
`-v /home/user/site:/usr/share/nginx/html`
- 내 컴퓨터에서 파일을 고치면 **컨테이너에 즉시 반영**. 개발 중 "변경 반영" 확인용.
- 경로가 내 컴퓨터에 종속돼서 다른 사람 PC 에서는 경로를 바꿔야 한다.

### 볼륨 (Volume)
Docker 가 **직접 관리하는 저장 공간**. 이름만 붙여 쓴다.
```
docker volume create mydata
docker run -v mydata:/data ...
```
- 컨테이너를 지워도 볼륨은 남는다. 새 컨테이너에 같은 볼륨을 붙이면 데이터가 그대로 있다.
- DB 데이터처럼 **오래 보관할 데이터**용.

### 바인드 마운트 vs 볼륨

| | 바인드 마운트 | 볼륨 |
|---|---|---|
| 위치 | 내가 정한 호스트 폴더 | Docker 가 관리하는 곳 |
| 용도 | 개발 중 코드 실시간 반영 | 데이터 영속 보관 |
| 이식성 | 낮음 (경로 종속) | 높음 (이름만 맞으면 됨) |
| 과제 증거 | 호스트 파일 변경 전/후 | 컨테이너 삭제 전/후 |

## 9. Git · GitHub

### 버전 관리 (Version Control)
파일의 **변경 이력을 기록**해서 언제든 과거로 돌아가거나, 누가 무엇을 바꿨는지 볼 수 있게 하는 것.

### Git
내 컴퓨터에서 돌아가는 **버전 관리 프로그램**. 인터넷 없이도 동작한다.

### GitHub
Git 저장소를 **인터넷에 올려 공유·협업하는 서비스**. Git 이 도구라면 GitHub 는 그 도구로 만든 결과물을 올리는 웹사이트.
비슷한 서비스: GitLab, Bitbucket.

### 저장소 (Repository, repo)
Git 이 관리하는 프로젝트 폴더. `.git` 숨김 폴더에 모든 이력이 들어 있다.
- **로컬 저장소**: 내 컴퓨터
- **원격 저장소(remote)**: GitHub 에 있는 것. 보통 `origin` 이라 부른다

### 커밋 (Commit)
"지금 상태를 기록해 둔다"는 **저장 지점**. 메시지를 함께 남긴다.
`git add 파일` (기록할 파일 고르기, 스테이징) → `git commit -m "메시지"`

### 브랜치 (Branch)
작업 흐름의 **갈래**. 원본(main)을 건드리지 않고 따로 작업한 뒤 합친다.
- **기본 브랜치**: 저장소를 만들 때 처음 생기는 브랜치. 요즘은 `main`, 예전엔 `master`.
- `git config --global init.defaultBranch main` 으로 기본값을 정한다 (과제 요구 항목).

### push / pull / clone
- `push`: 내 커밋을 GitHub 로 올리기
- `pull`: GitHub 의 변경을 내 컴퓨터로 받기
- `clone`: GitHub 저장소를 통째로 내 컴퓨터에 복사

### git config
Git 설정. `--global` 은 이 컴퓨터 전체, 없으면 현재 저장소만.
```
git config --global user.name "이름"
git config --global user.email "메일"
git config --list
```
커밋에 "누가 했는지" 찍히므로 이름·메일 설정은 필수.

### HTTPS vs SSH (보너스)
GitHub 에 연결하는 두 가지 방법.
- **HTTPS**: 주소가 `https://github.com/...`. 토큰(비밀번호 대용)으로 인증.
- **SSH**: 주소가 `git@github.com:...`. 내 컴퓨터의 **키 쌍**(공개키·개인키)으로 인증. 공개키만 GitHub 에 등록하고, 개인키는 절대 밖으로 내보내지 않는다.

### 토큰 / 개인키 (민감정보)
비밀번호와 같은 효력. README·스크린샷·커밋에 **절대 넣지 않는다**. 실수로 올렸으면 즉시 폐기하고 다시 발급.

## 10. 보너스 과제 용어

### Docker Compose
여러 컨테이너의 실행 설정을 `docker-compose.yml` **파일 하나에 적어 두고** 한 번에 켜고 끄는 도구.
긴 `docker run` 명령이 "문서화된 설정"으로 바뀐다.

```yaml
services:
  web:
    build: .
    ports:
      - "8080:80"
```

| 명령 | 뜻 |
|---|---|
| `docker compose up -d` | 설정대로 전부 실행 |
| `docker compose down` | 전부 정지·삭제 |
| `docker compose ps` | 상태 보기 |
| `docker compose logs` | 로그 보기 |

### 서비스 디스커버리
Compose 로 띄운 컨테이너끼리는 **서비스 이름이 곧 주소**다. web 컨테이너에서 `http://db:5432` 로 db 컨테이너에 닿는다. IP 를 몰라도 된다.

### 환경 변수 (Environment Variable)
프로그램 밖에서 넣어 주는 설정값. 코드를 안 고치고 포트·모드를 바꿀 수 있다 (설정과 코드의 분리).
`docker run -e PORT=5000 ...`, Dockerfile 의 `ENV`, Compose 의 `environment:`.

### YAML
Compose 파일 형식. 들여쓰기(공백 2칸)로 구조를 표현한다. **탭 금지**.

## 11. 시험 대비 — 과제 목표 6문항 모범 답안

**Q1. 절대 경로와 상대 경로의 차이를 예시를 들어 설명하라.**
절대 경로는 루트(`/`)부터 적은 전체 주소로, 어디서 실행해도 같은 곳을 가리킨다 (예: `/home/user/app/index.html`).
상대 경로는 현재 위치를 기준으로 적은 주소라 위치에 따라 결과가 달라진다 (예: `/home/user/app` 에서 `./index.html` 은 위 파일, `/tmp` 에서 치면 `/tmp/index.html`).
`.` 은 현재 폴더, `..` 은 상위 폴더.

**Q2. r/w/x 의 의미와 755, 644 해석 규칙.**
r=읽기(4), w=쓰기(2), x=실행(1). 세 자리는 순서대로 소유자·그룹·기타에게 주는 권한이고, 각 자리는 r+w+x 값의 합이다.
755 = 소유자 rwx(7), 그룹 r-x(5), 기타 r-x(5) → 실행 파일·디렉토리.
644 = 소유자 rw-(6), 그룹 r--(4), 기타 r--(4) → 일반 문서.
디렉토리에서 x 는 "안으로 들어갈 수 있다"는 뜻이라 디렉토리는 보통 755.

**Q3. 기존 Dockerfile 기반 커스텀 이미지를 만드는 방법.**
`FROM` 으로 베이스 이미지(예: `nginx:alpine`)를 지정하고, `COPY` 로 내 정적 파일을 웹 루트에 덮어쓰고, `ENV`·`LABEL` 등으로 설정을 추가한 뒤 `docker build -t 이름:태그 .` 로 빌드한다.
베이스가 이미 웹 서버를 갖고 있으니 나는 콘텐츠와 설정만 바꾸면 된다.

**Q4. 포트 매핑이 필요한 이유.**
컨테이너는 격리된 네트워크를 쓰므로 안에서 웹 서버가 떠 있어도 호스트에서 직접 접근할 수 없다.
`-p 호스트포트:컨테이너포트` 로 호스트의 포트를 컨테이너 포트에 연결해야 브라우저에서 `localhost:호스트포트` 로 접속된다.
호스트 포트를 다르게 주면 같은 이미지를 여러 개 동시에 띄울 수 있다.

**Q5. Docker 볼륨(영속 데이터)을 설명하라.**
컨테이너 안의 파일은 컨테이너를 삭제하면 함께 사라진다. 볼륨은 Docker 가 컨테이너와 별도로 관리하는 저장 공간으로, `docker volume create` 로 만들고 `-v 볼륨명:경로` 로 연결한다.
컨테이너를 지우고 새로 만들어 같은 볼륨을 붙이면 데이터가 그대로 남아 있다. 바인드 마운트는 호스트 폴더를 직접 연결하는 방식으로, 개발 중 변경 반영에 쓴다.

**Q6. Git 과 GitHub 의 역할 차이.**
Git 은 내 컴퓨터에서 동작하는 버전 관리 도구로, 커밋·브랜치·이력 조회를 인터넷 없이 처리한다.
GitHub 는 Git 저장소를 인터넷에 올려 공유하고 협업(PR, 이슈, 리뷰)하는 원격 플랫폼이다.
Git 없이 GitHub 는 못 쓰지만, GitHub 없이 Git 은 쓸 수 있다.

## 12. 헷갈리기 쉬운 짝

| 짝 | 한 줄 구분 |
|---|---|
| 이미지 / 컨테이너 | 틀 / 틀로 찍어낸 실체 |
| `docker ps` / `docker ps -a` | 실행 중만 / 멈춘 것까지 |
| attach / exec | 메인 프로세스에 붙기(나가면 종료) / 새 프로세스 띄우기(나가도 유지) |
| RUN / CMD | 빌드 때 한 번 / 시작할 때마다 |
| EXPOSE / `-p` | 문서용 표시 / 실제 연결 |
| 바인드 마운트 / 볼륨 | 호스트 폴더 직접 연결 / Docker 관리 저장소 |
| `rm` / `rmi` | 컨테이너 삭제 / 이미지 삭제 |
| Git / GitHub | 로컬 도구 / 원격 협업 서비스 |
| `git add` / `git commit` | 기록할 파일 고르기 / 실제로 기록 |
| push / pull | 올리기 / 받기 |
| HTTPS / SSH | 토큰 인증 / 키 쌍 인증 |
| 절대 경로 / 상대 경로 | `/` 부터 / 현재 위치부터 |
